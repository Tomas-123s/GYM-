# المرحلة 5 — الجودة والتكامل والتسليم (الأيام 15–16)

**الهدف:** تسليم MVP موثق وقابل للتشغيل، مع التحقق من أهم المسارات الحرجة.

## المهام

### التكامل ومراجعة النطاق
- [ ] إكمال ربط React بالـAPI الفعلي لكل تدفق رئيسي؛ إزالة بيانات العرض الثابتة.
- [ ] فحص صفحات الدخول واللوحة والأعضاء والخطط والاشتراكات والدفعات والحضور والتدريب والقياسات والإشعارات والتقارير.
- [ ] مراجعة RTL، تنسيق EGP والتاريخ، حالات التحميل والفراغ والخطأ والنجاح، التصفح على الهاتف، الترقيم والبحث.
- [ ] تدقيق صلاحيات كل endpoint وكل استعلام عضو/مال، وعدم كشف تفاصيل استثناء داخلية.
- [ ] مراجعة القيود والعلاقات والفهارس وعمليات migration، وعدم حذف بيانات تاريخية عرضًا.

### التحقق
- [ ] تشغيل اختبارات وحدة لحساب تواريخ الاشتراكات والأرصدة.
- [ ] تشغيل اختبارات تكامل لنقاط API الحرجة.
- [ ] اختبار Admin مقابل Coach، وحساب معطل، وطلب غير موثق، وبيانات خارج نطاق المدرب.
- [ ] اختبار الحضور المكرر والمتزامن، والمدفوعات الجزئية والاستردادات والتقارير وCSV العربي.
- [ ] إصلاح العيوب الحرجة المالية والأمنية والبياناتية.

### التسليم
- [ ] README لتثبيت وتشغيل frontend/backend وSQL Server وتطبيق migrations.
- [ ] توثيق متغيرات البيئة في ملف مثال بلا قيم سرية.
- [ ] إضافة بيانات demo خيالية وحسابي Admin وCoach بطريقة آمنة موثقة محليًا.
- [ ] توثيق النسخ الاحتياطي والاستعادة، سياسة المنطقة الزمنية، قواعد العمل، API عبر Swagger والقيود المعروفة.
- [ ] توفير نشر تجريبي إذا كان ممكنًا؛ وإلا خطوات تشغيل محلي موثقة.

## معيار الإنجاز وتعريف الاكتمال

- جميع متطلبات Must ضمن MVP مكتملة، مع بقاء القيود المعروفة موثقة.
- سيناريوهات القبول الحرجة تعمل، والواجهة تستخدم API الحقيقي.
- لا توجد ثغرة صلاحيات أو خلل جوهري معروف في المال أو سلامة البيانات.
- المشروع قابل للتشغيل وفق README ويحتوي migrations وبيانات تجريبية وتوثيقًا.
