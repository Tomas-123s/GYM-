# FitManager — خطة التنفيذ

> مصدر الخطة: BRD الإصدار 1.0 بتاريخ 28 أكتوبر 2026. هذه الملفات تقسّم نطاق MVP إلى مراحل قابلة للتنفيذ، مع إبقاء معرّفات المتطلبات الأصلية لتسهيل التتبع.

## التقنية والهيكل المعتمد

- **Backend:** ASP.NET Core Web API بـ C#، مع فصل ثلاثي الطبقات منطقي: **Presentation/API** لاستقبال HTTP والتحقق من الهوية، **Business/Application** لقواعد العمل وحالات الاستخدام، و**Data Access/Infrastructure** لـ EF Core وSQL Server.
- **Frontend:** React وTypeScript، React Router، TanStack Query (أو بديل مكافئ)، نماذج موثقة والتحقق منها، ودعم العربية RTL.
- **Database:** Microsoft SQL Server عبر Entity Framework Core وmigrations. استخدم ASP.NET Core Identity للمستخدمين والأدوار.
- الطبقات الثلاث مشاريع/مكونات منفصلة بمراجع اتجاه واحد: API → Application → Infrastructure؛ لا تضع قواعد العمل في Controllers أو الواجهة.
- احسب الأموال بـ `decimal`، واحتفظ بالأسعار عند الشراء. التاريخ المحلي للنادي يُضبط صراحةً، مع فصل تاريخ الحضور عن وقت تسجيل الدخول.

## ترتيب التنفيذ والتبعيات

1. أنجز المرحلة 0 قبل بناء الوحدات: هيكل المشاريع، إعداد SQL Server/EF Core، سياسة التاريخ، الهوية والصلاحيات.
2. المرحلة 1 تؤسس بيانات الأعضاء والخطط التي تعتمد عليها المدفوعات والحضور.
3. المرحلة 2 تعتمد على اشتراكات المرحلة 1؛ أنجز قيود SQL والتعامل الذري مع المعاملات.
4. المرحلة 3 تستفيد من العضو والمستخدم والأدوار.
5. المرحلة 4 تجمع بيانات المراحل السابقة؛ عرّف صيغ الأرقام والفترات قبل عرضها.
6. نفّذ اختبارات كل قاعدة عمل مع مرحلتها، ثم أكمل مراجعة التكامل والتسليم في المرحلة 5.

## النطاق والقيود

يشمل MVP: المصادقة، Admin/Coach، الأعضاء، الخطط والاشتراكات، الدفعات والأرصدة، الحضور، إشعارات انتهاء الاشتراك داخل التطبيق، الخطط التدريبية والتمارين والقياسات، لوحة وتقارير، CSV، واجهة RTL، migrations، seed واختبارات القواعد الحرجة وتوثيق التشغيل.

خارج الإصدار الأول: تطبيقات هاتف أصلية، بوابة دفع، SMS/WhatsApp، الرواتب والمحاسبة الكاملة، الفروع المتعددة، المخزون، التغذية المتقدمة، جدولة الحصص، الدفع المتكرر، وأجهزة البصمة.

## قواعد المشروع

- لا حذف دائم للسجلات المالية أو التاريخية؛ استخدم الأرشفة أو تسويات قابلة للتدقيق.
- تحقق الصلاحيات في الـBackend على كل endpoint، وقيد وصول المدرب بالأعضاء المصرح بهم.
- قواعد المال والاشتراك والحضور تنفذ في طبقة التطبيق وتحمى بقيود قاعدة البيانات عند الحاجة.
- لا تعتبر الإيراد والتحصيل النقدي مقياسًا واحدًا إلا بسياسة محاسبية موثقة.
- راجع [BRD الأصلي](../) عند الحاجة إلى النص الكامل للمتطلبات. معرّفات المتطلبات الواردة هنا تشير إلى أقسام BRD.
