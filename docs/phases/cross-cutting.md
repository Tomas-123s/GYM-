# متطلبات مشتركة لكل المراحل

## المعمارية ثلاثية الطبقات

1. **Presentation — ASP.NET Core API:** Controllers/Endpoints، HTTP status codes، المصادقة، DTOs، والتحقق الأولي. لا تحسب المال ولا تضع قواعد المجال هنا.
2. **Business/Application:** حالات الاستخدام والخدمات وقواعد النطاق: التجديد، التحقق المالي، أهلية الحضور، الصلاحيات على مستوى السجل، واحتساب التقارير. تعتمد على تجريدات لا على تفاصيل SQL Server.
3. **Data Access/Infrastructure:** EF Core، Identity persistence، repositories عند الحاجة، تنفيذ التخزين، SQL Server، migrations، المعاملات والتكاملات.

يمكن أن يكون Domain مشروعًا مستقلًا ضمن/بجوار طبقة الأعمال. يجب أن يبقى اتجاه الاعتماد من API إلى Application، ومن Infrastructure إلى abstractions التي تحتاجها Application؛ تجنب الاعتماد الدائري. React تطبيق العميل ويتواصل عبر API، وليس طبقة من طبقات الخادم الثلاث.

## متطلبات البيانات والسلامة

- SQL Server وEF Core؛ مفاتيح أجنبية وفهارس للبحث، وقيود فريدة للقواعد الحرجة.
- `decimal` للأموال، وقيم محفوظة للسعر والخصم وقت الشراء.
- قيود فريدة لكود العضو ومرجع المعاملة و(MemberId, AttendanceDate).
- معاملات قاعدة بيانات للعمليات التي يجب أن تنجح/تفشل معًا، مع مراعاة التزامن.
- لا حذف دائم للدفعات والحضور والسجلات التاريخية؛ سجل Audit للعمليات الحساسة.
- migrations لكل تغيير، وسياسة حذف FK تمنع فقدان التاريخ.

## الأمن والخصوصية

- ASP.NET Core Identity؛ كلمات المرور لا تخزن كنص واضح، الأسرار خارج المصدر.
- فرض Admin/Coach على كل endpoint من الخادم؛ عدم الاعتماد على إخفاء عناصر الواجهة.
- عزل سجل المدرب إلى الأعضاء المخولين فقط، بما يشمل البحث والتقارير والـIDs المباشرة.
- التحقق من كل إدخال على الخادم، واستجابات أخطاء موحدة وآمنة، وتسجيل تشغيلي لا يكشف بيانات حساسة.
- تحديد استراتيجية Cookie/Token آمنة وتوثيقها، وحماية بيانات الأعضاء والمال.

## الواجهة وتجربة الاستخدام

- React + TypeScript، واجهة عربية RTL ومتجاوبة، تنسيق موحد للتاريخ وEGP.
- pagination، بحث وفرز وفلاتر للقوائم الكبيرة؛ تسميات حقول واضحة وتباين مقروء.
- حالات تحميل/فراغ/نجاح/خطأ ورسائل تحقق مفهومة؛ تأكيد الإجراءات الحساسة.
- قوائم ومسارات تتكيف مع الدور، مع بقاء القرار الأمني في الـAPI.

## التشغيل والتوثيق

- إعدادات بيئية للاتصال والأسرار؛ نسخة مثال لا تتضمن أسرارًا حقيقية.
- بيانات تجريبية خيالية، خطوات محلية، migrations، Swagger، وبيانات دخول demo آمنة.
- توثيق نسخ SQL Server الاحتياطي والاستعادة، المنطقة الزمنية، وتعريف تقارير المال.

## متطلبات اختبار أصلية

اختبارات وحدة لتواريخ الاشتراك والرصيد، وتكامل لنقاط API الحرجة، وصلاحيات Admin/Coach، الحضور المكرر/المتزامن، المبالغ غير الصحيحة، التقارير وتصدير CSV. نفذها في المراحل المذكورة ثم راجعها في المرحلة 5.
